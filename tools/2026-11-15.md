# AI 工具日报 2026-11-15

## AI 工具类

**1. Cursor 承认遭入侵：恶意 Claude Code 扩展 2.1.312/2.1.313 混入市场缓存，至多 5,000 人可能中招**

Cursor 11 月 13 日事件报告：发给 Fireworks AI 的访问密钥泄露，攻击者用它从只读共享存储桶复制历史 coding-agent traces（含未脱敏凭据），10 月 29 日把篡改版 Anthropic Claude Code 扩展 2.1.312 与 2.1.313 放入 Cursor 的 VS Code 扩展市场缓存，存活约 11 小时（太平洋时间 02:27–13:35）；至多 5,000 名用户可能收到恶意构建，装后植入持久 SSH 后门（svc-telemetry 密钥，反向隧道到 134.209.82.225、扫环境变量）；少于 0.05% 用户的 traces 被暴露、少于 0.01% 客户的 API 凭据被暴露。Cursor 已把推理流量全部迁出 Fireworks、吊销密钥、轮换凭据、重建市场；最后一次攻击者活动 11 月 1 日，已阻断；Anthropic 系统未被入侵，Open VSX 从未托管恶意版本。Fireworks 另有一起 10 月 23–24 日的独立事件（经第三方云服务商，LLMjacking 团伙）。

为什么值得知道：自查就三步——查扩展版本是不是 2.1.312/2.1.313、查 SSH 授权密钥里有没有 svc-telemetry、升级到 2.1.314 并按 Cursor 安全公告的清理脚本走一遍；只卸载扩展可能清不干净。10 月 29 日前后在 Cursor 里装过 Claude Code 扩展的人，今天就该查。

来源：[2-spyware（11 月 15 日）](https://www.2-spyware.com/cursor-confirms-breach-behind-fake-claude-code-extension)、[AI Agent Update（11 月 14 日）](https://aiagentupdate.com/post/cursor-breach-fireworks-key-2026-11-14)

注：同一事件见早报第一部分第 1 条。

**2. Claude Code 2.1.325（11 月 13 日）：zstd 安全修复 + 沙箱 Bash 改默认要确认**

Claude Code 2.1.325（11 月 13 日发布，139 条 changelog）：修复 zstd 压缩响应解码的安全问题（changelog 只写一句话，未给 CVE、未列受影响版本、未描述利用路径）；沙箱里的 Bash 命令改走正常权限流程（默认要确认，想恢复旧行为设 sandbox.autoAllowBashIfSandboxed: true）；修复子代理自带模型被 plan-mode 模型顶掉的问题；修复会话恢复时异常退出导致的状态损坏（改写临时文件再原子重命名）。同周：2.1.323（11 月 12 日）加了实验性 Code Mode（Claude 直接写 JavaScript 批量调工具）。

为什么值得知道：zstd 那行没给细节，但它是安全修复——先升到 2.1.325 再说；沙箱 Bash 改默认要确认是行为变化，跑自动化脚本的人升级后先看一眼是不是多了确认弹窗。

来源：[Gradually Claude Code Changelog（11 月 13 日）](https://www.gradually.ai/en/changelogs/claude-code/)、[Subagentic（11 月 14 日）](https://subagentic.ai/posts/claude-code-2-1-325-zstd/)、[AgenticMart（11 月 14 日）](https://agenticmart.org/blog/ai-coding-agent-news-november-2026)

**3. Google Antigravity 上线 Dynamic Workflows（11 月 13 日）：agent 小队按 Python 脚本跑**

谷歌 Antigravity 11 月 13 日推出 Dynamic Workflows：开发者用一段可读的 Python 脚本协调多个 AI coding agent 并行工作，脚本先给人看、再执行。同日 Anthropic 发布 Claude Code 2.1.325（见上条）。Antigravity 的打法是"编排可读"——agent 怎么分工、谁先谁后，写在脚本里而不是藏在黑盒调度里。

为什么值得知道：多 agent 从"一个 agent 干到底"进入"小队按脚本分工"的阶段；脚本可读意味着出问题能定位到某一步，而不是对着黑盒猜。跑多 agent 流程的团队，可以拿它跟 Claude Code 的 agent teams（实验性，默认关闭）对照着看。

来源：[Inoryva（11 月 14 日）](http://inoryva.blogspot.com/2026/11/google-antigravity-dynamic-workflows.html)、[ClaudeBeat（11 月 14 日）](https://www.claudebeat.ai/articles/2026/11/2026-11-14.html)

**4. Memro 上线（11 月 14 日）：Go 写的持久记忆系统，MCP + PostgreSQL，让 coding agent 跨会话共享上下文**

Memro 11 月 14 日上线：Go 编写的持久记忆系统，基于 MCP + PostgreSQL（pgvector），让 Claude Code、Cursor、Codex 跨会话共享上下文与项目状态；MCP 暴露 remember、recall 等 5 个工具，一条 npx memro-cli connect 自动配好 9 个客户端（Claude Code、Cursor、Codex、VS Code、Claude Desktop、Antigravity、Windsurf、OpenCode、Gemini CLI）；PolyForm 非商业许可，个人免费、商用要订阅；仓库 10 月 18 日建，发布时仅 6 个 star，尚处早期。同日 Dev.to 有一篇实战手记，记录了四家 agent 各自的配置坑（见早报第二部分第 2 条）。

为什么值得知道：多 agent 共用记忆的坑不在"接不接得上"，在每家配置优先级不一样——Memro 把接线做成一条命令，剩下的坑在各家文档里；项目刚上线（6 star），先在小项目试，别直接当生产记忆用。

来源：[Emergent（11 月 14 日）](https://emergent.sh/news/memro-launches-persistent-memory-claude-code)、[Dev.to（11 月 14 日）](https://dev.to/delimitter/memro-a-memory-layer-for-ai-agents-with-typed-memory-and-mcp-over-postgresql-46ag)

Cursor 新客自 10 月 12 日起走 The X Subscription（SpaceXSI 推出，捆 Grok、Grok Bot、Cursor 与 X Premium）：Free $0、Plus $8/月（年付 $80）、Premium $30/月（年付 $300）、Super $100/月、Ultra $200/月；每档一个每周用量池，在 Grok 与 Cursor 间共享，按 Plus 的 1x/4x/15x/50x 计；池子只含自家模型（Grok 与 Composer），第三方模型（Claude、GPT、Gemini）按 API 价从预付充值里扣，Plus 与 Free 不能用第三方模型；老计划（Cursor Pro $20 等）可继续用、切换自愿且不可逆。Cursor 2026.11.06（11 月 6 日）加了实时语音聊天。

**1. Veo 3.1 时间线纠正：Flow 里 12 月 5 日才下线，11 月 17 日不是 Flow 的死线**

昨天本报写的"Veo 3.1 停用倒计时 3 天：11 月 17 日"容易看错，特此纠正：11 月 17 日是 Google Cloud 模型页的提示时间；Google Flow 帮助页的原文是"On December 5, 2026, Veo 3.1 Fast, Veo 3.1 Quality, and Omni Flash 1.1 will be retired"——Flow 内 Veo 3.1 Fast/Quality 12 月 5 日才退役，在此之前照常按标准 credit 价生成（Quality 8 秒 100 credits、Fast 20 credits）；12 月 5 日后 Flow 只剩 Omni Flash 1.2 与 Veo 3.1 Lite；Veo Extend 已于 11 月 5 日退役；Gemini API 的 Veo 3.1 预览模型已于 10 月 22 日下线。Flow 内 Veo 3.1 Quality/Fast 标注的正是 12 月 5 日。

为什么值得知道：还在用 Veo 3.1 出片的人不用赶 11 月 17 日——窗口是到 12 月 5 日，12 月 5 日前按原方案重跑都行；但新项目谷歌已建议切 Omni Flash 1.2 或 Veo 3.1 Lite，别再往 Fast/Quality 上搭长期流程。
