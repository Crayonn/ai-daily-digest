## 第二部分：技术分享·好实践

**1. 《One AGENTS.md to rule Claude Code, Cursor and Codex》(dev.to, 10-14)**

http://dev.to/mars_peakul/one-agentsmd-to-rule-claude-code-cursor-and-codex-3jmi

讲了什么：用一个主 AGENTS.md 统一指挥三个 coding agent，各工具配置只留薄薄一层引用。

为什么有效：标题借"魔戒体"一眼定调，正文用"主文件 vs 薄配置"对比结构，每条规则配可复制的文件路径。

可借一招：写工具教程先定"一个主文件管一切"的中心隐喻，再给复制即用的路径。

**2. 《What Claude Code Teaches Us About Building Reliable AI Agents》(LinkedIn, 10-1)**

https://www.linkedin.com/pulse/what-claude-code-teaches-us-building-reliable-ai-agents-rahim-o9mqc

讲了什么：拆 Claude Code 的设计，论证 agent 的可靠性来自模型之外的脚手架。

为什么有效：开头就是反直觉结论"可靠性来自脚手架，不来自模型"，再用 compaction 三阶段这种可验证的内部机制撑住。

可借一招："反直觉结论先行 + 一个可验证的内部机制"，比堆功能列表更容易被转发。

**3. Simon Willison《Claude Haiku 5.5》(10-7)**

https://simonwillison.net/2026/Oct/7/claude-haiku-5-5/

讲了什么：Haiku 5.5 发布当天即上手实测：真实 prompt、真实输出、价格账。

为什么有效：速度（发布 24 小时内）+ 证据（贴实际输出不转述）+ 成本视角，这是他每篇模型帖都被转的固定配方。

可借一招：新模型/工具发布后 24 小时内发"上手实测 + 帮你算了价格"，时效本身就是钩子。

**4. 《Gemini 4 Argon vs GPT-6 Astra vs Claude：价格与可用性对照》(dev.to, 10-12)**

http://dev.to/rainytechlab/gemini-4-argon-vs-gpt-6-astra-vs-claude-api-pricing-and-access-for-developers-october-2026-2lh9

讲了什么：三家旗舰模型的价格表 + "今天能不能调用"的可用性对照，数字全部注明来自厂商自己页面。

为什么有效：钩子是"价格只是一半问题，另一半是今天能不能用"——双维表格一次回答两个决策问题，且声明"非亲测、数字全来自官方"，反而更可信。

可借一招：做横评用"价格 × 可用性"双列表格，明确标注每条数据的来源。
