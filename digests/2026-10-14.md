## 第二部分：技术分享·好实践

### 1. 《给 agent 的上下文不是越多越好》
dev.to 博主拆解了为什么塞满整个 repo 反而让 agent 变笨：把"永久规则"和"任务上下文"分开，永久规则保持短小。
为什么有效：反直觉钩子（"more context, worse results"），一句话就让人想点开。
借的一招：开工前先让 agent 自己回答四问——需要什么信息、哪些文件相关、现在在做什么假设、什么上下文能降低不确定性。
https://dev.to/robertadam987_/the-more-context-you-give-your-ai-coding-agent-the-worse-it-can-get-4d40

### 2. 《2026 年给 AI 编程 agent 上沙箱的完整指南》
codersera 的实操文：从文件系统、网络、凭证、git 四个维度限定 agent 权限，每条都对应具体配置项。
为什么有效：纯清单结构，没有一句废话，读者照抄就能落地。
借的一招：教程结尾附"四维度自查表"，把文章变成工具，收藏率直接拉高。
https://codersera.com/blog/how-to-sandbox-ai-coding-agents-2026/

### 3. 《终端 vs 桌面：编程 agent 的 CLI 时代结束了吗》
explainx 用一张决策表终结争论：单任务看终端、多并行要状态视图、跨项目直接上 orchestrator。
为什么有效：把"X vs Y"口水战变成"你的场景→选哪个→为什么"的三列表，读者对号入座。
借的一招：任何对比帖都配一张三列决策表，这是转发率最高的形态。
https://explainx.ai/blog/terminal-era-over-agent-is-the-new-primitive-claude-code-codex-desktop-2026

### 4. LinkedIn 热帖：造 agent 前要懂的 9 个概念
GenAI Works 的清单帖：agentic loop、MCP、subagent、推理经济学、eval、护栏、可观测性、agent harness，每条一句话讲清。
为什么有效：数字清单降低阅读压力，结尾反问"你的 agent 还缺哪一个"直接要评论。
借的一招：清单帖结尾加一个点名式提问，把"看完就走"变成"评论区对号入座"。
https://www.linkedin.com/posts/genai-works_top-things-you-need-to-know-before-building-activity-7513916150800547841-GN_L
